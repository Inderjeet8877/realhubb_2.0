# RealHubb — Real Estate Web Platform

Production website for **RealHubb Ventures Pvt. Ltd.**, a real estate channel partner operating across Bangalore, Hyderabad, and Chennai. The platform exposes a public-facing property listing site and a password-protected admin CMS backed by Firebase Firestore and Cloudinary.

**Live URL:** https://www.realhubb.in  
**Repository:** https://github.com/Inderjeet8877/realhubb_2.0  
**Stack:** React 18 + TypeScript + Vite + Tailwind CSS + Firebase + Cloudinary

## Environment Variables

Create a `.env` file at project root. All browser-exposed variables must be prefixed `VITE_`.

```env
# ── Firebase ─────────────────────────────────────────────────────────────────
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=

# ── Cloudinary ───────────────────────────────────────────────────────────────
VITE_CLOUDINARY_CLOUD_NAME=
VITE_CLOUDINARY_UPLOAD_PRESET=      # Must be an unsigned preset

# ── Web Push (server-side only — set in Vercel dashboard, NOT in .env) ───────
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=mailto:info@realhubb.in
```

> `VAPID_*` variables have no `VITE_` prefix — they are only used by the Vercel serverless function `/api/send-notification.ts` and must be set in Vercel's environment variable dashboard.

### URL-Driven State — Projects Page

The Projects page derives all display state from the URL — no independent `useState` for city/type:

```
/projects/ongoing/bangalore?type=apartment&price=10000000-20000000
         ───┬───  ────┬────  ────┬──────── ─────────────┬──────────
            │         │          │                       │
        projectType  activeCity  filter.type         filter.priceRange
        (useParams)  (useParams) (useSearchParams)   (useSearchParams)
```

City and type toggles call `navigate()`. The `?type` and `?price` query params are written by the Hero Quick Search and read on component mount to pre-populate the `PropertySearchFilter`.

## Data Layer

### Firestore-first with Static Fallback

Every data hook follows the same resilience pattern:

```
Firestore fetch
  ├── success + data.length > 0  → render Firestore data
  ├── success + data.length === 0 → render static /data/ fallback
  └── error                      → render static /data/ fallback
```

This keeps the site fully functional without a Firestore connection and makes local development possible without credentials.

### Firestore Service (`src/lib/firestoreService.ts`)

Single file, all Firestore operations. Naming convention: `{verb}{Collection}`:

| Function | Collection | Operation |
|---|---|---|
| `getProperties()` | `properties` | Read all |
| `addProperty(data)` | `properties` | Create + auto push notif |
| `updateProperty(id, data)` | `properties` | Update |
| `deleteProperty(id)` | `properties` | Delete |
| `seedProperties(arr)` | `properties` | Bulk create |
| `getBlogPosts()` | `blogPosts` | Read all |
| `addBlogPost(data)` | `blogPosts` | Create + push notif if published |
| `updateBlogPost(id, data)` | `blogPosts` | Update |
| `deleteBlogPost(id)` | `blogPosts` | Delete |
| `getDevelopers()` | `developers` | Read all |
| `addDeveloper(data)` | `developers` | Create |
| `updateDeveloper(id, data)` | `developers` | Update |
| `deleteDeveloper(id)` | `developers` | Delete |
| `getTeamMembers()` | `team` | Read all |
| `addTeamMember(data)` | `team` | Create |
| `updateTeamMember(id, data)` | `team` | Update |
| `deleteTeamMember(id)` | `team` | Delete |
| `getGalleryPosts()` | `gallery` | Read all |

## Firestore Collections & Data Models

### `properties`

```ts
{
  id:          string;        // Auto Firestore doc ID
  slug:        string;        // URL slug, e.g. "godrej-aveline-yelahanka"
  name:        string;        // Display name
  developer:   string;        // Developer name
  city:        "bangalore" | "hyderabad" | "chennai";
  location:    string;        // Locality, e.g. "Yelahanka"
  status:      "ongoing" | "upcoming";
  type:        "apartment" | "villa" | "plot" | "commercial";
  price:       string;        // Display string, e.g. "₹85 L onwards"
  priceValue:  number;        // Numeric rupees value — used for range filter
  area:        string;        // e.g. "1200–2400 sq.ft"
  bedrooms:    string;        // e.g. "2BHK, 3BHK"
  images:      string[];      // Array of Cloudinary secure_url values
  rera:        string;        // RERA registration number
  possession:  string;        // e.g. "Dec 2026"
  description: string;        // Full description (plain text or Markdown)
  featured:    boolean;       // Floats to top of listing
  amenities:   string[];      // e.g. ["Swimming Pool", "Gym"]
  mapEmbedUrl: string;        // Google Maps embed src URL
  projectType: "ongoing" | "upcoming";  // Primary category field
  createdAt:   Timestamp;
  updatedAt:   Timestamp;
}
```

**Filtering logic** in `applyFilters()` (`src/pages/Projects.tsx`):

- **City** — exact match `p.city.toLowerCase() === cityKey`
- **BHK** — exact match `p.bhk || p.bedrooms`
- **Type** — exact match `p.type.toLowerCase()`
- **Price range** — `p.priceValue >= min && p.priceValue <= max`
- **Search** — substring match on `title | name | location`
- **Sort** — `featured === true` floats to top

## Cloudinary Image Pipeline

### Folders

All uploads go into subfolders under the `realhubb/` root:

```
realhubb/
  properties/   → property photos
  blogs/        → blog cover images
  developers/   → developer logos
  team/         → team member photos
  gallery/      → gallery post images
```

### Upload

Uses an **unsigned upload preset** — no API secret is ever in the browser bundle. The `CloudinaryFolder` type (`src/lib/cloudinary.ts`) enforces valid folder values at compile time.

### Optimisation Presets

`imagePresets` in `src/lib/cloudinary.ts` applies Cloudinary URL transforms:

```ts
imagePresets.propertyCard(url)   // 600×400,  auto format/quality, fill crop
imagePresets.propertyHero(url)   // 1200×675, auto format/quality, fill crop
imagePresets.blogCover(url)      // 800×450,  auto format/quality, fill crop
```

## Push Notifications

### Architecture

```
User clicks bell → useNotifications.subscribe()
  → requestNotificationPermission()
  → navigator.serviceWorker.ready.pushManager.subscribe()
  → save PushSubscription to Firestore /pushSubscriptions/{deviceId}

Admin creates property / publishes blog post
  → firestoreService calls sendNotification(payload)
  → sendNotification() reads ALL /pushSubscriptions from Firestore
  → chunks into batches of 100
  → POST /api/send-notification (Vercel serverless function)
  → Vercel uses web-push library → delivers to each browser
  → Expired subscriptions (410/404) returned by server
  → Cleaned from Firestore automatically
```

### Vercel Function

`/api/send-notification.ts` requires these environment variables set in Vercel dashboard:

- `VAPID_PUBLIC_KEY`
- `VAPID_PRIVATE_KEY`
- `VAPID_SUBJECT` = `mailto:info@realhubb.in`

## Key Patterns & Conventions

### Path alias

`@` resolves to `src/` in both Vite and TypeScript configs:

```ts
import { useProperties } from "@/hooks/Useproperties";
```

### Hook file naming

Custom hooks use PascalCase-ish names (`Useproperties.ts`, `Useblogposts.ts`). When rewriting, normalise to camelCase (`useProperties.ts`).

### `clean<T>()` — strip undefined before Firestore writes

Firestore rejects documents with `undefined` field values. Every write passes data through this helper:

```ts
function clean<T extends Record<string, unknown>>(obj: T): T {
  return Object.fromEntries(
    Object.entries(obj).filter(([, v]) => v !== undefined)
  ) as T;
}
```

### Property normalisation

`normalizeProperty()` in `useProperties.ts` maps raw Firestore/static data to the typed `Property` shape, resolves all legacy field aliases (`name` vs `title`, `image` vs `images`, `bedrooms` vs `bhk`), and applies Cloudinary presets once at load time.

### `projectType` field priority

A property is categorised using this priority order:

```ts
if (p.projectType === "upcoming") return "upcoming";
if (p.projectType === "ongoing")  return "ongoing";
if (p.status      === "upcoming") return "upcoming";
return "ongoing"; // default
```

Always set `projectType` explicitly on new documents to avoid relying on the `status` fallback.

### Scroll animations

Wrap any element to trigger a CSS fade-up when it enters the viewport:

```tsx
<FadeInOnScroll direction="up" delay={200}>
  <YourComponent />
</FadeInOnScroll>
```

Use `delay` (ms) to stagger items in a grid — keep under 300ms to avoid perceived slowness.
